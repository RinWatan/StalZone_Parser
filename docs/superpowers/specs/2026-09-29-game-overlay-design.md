# STALZONE: игровой оверлей

Согласованный сценарий: Windows, игра в безрамочном режиме. Работа ведётся
в `codex/game-overlay`; `main` и существующая сборка `dist/STALZONE.exe`
остаются доступными. Новый файл сборки — `dist/STALZONE-overlay.exe`.

## Поведение

- Приложение стартует компактной панелью поверх других окон.
- Панель показывает состояние анализа, до пяти лучших найденных сделок
  с названием, ценой покупки и расчётной прибылью, а также кнопки
  «Прогон», «Стоп», «Развернуть» и закрытия приложения.
- В компактном режиме «Прогон» запускает поиск «Выкуп».
- «Развернуть» показывает полный существующий интерфейс поверх игры:
  все вкладки, поиск, бюджет, выбор раздела и управление мониторингом.
- «Свернуть» возвращает компактный режим. Оба представления используют
  один экземпляр приложения, очередь результатов и рабочий поток.
  Переключение не перезапускает анализ, не очищает результаты и не меняет
  выбранную вкладку полного интерфейса.
- Оба режима перемещаются за верхнюю полосу. Положение и размер каждого
  режима сохраняются локально. Старт всегда компактный.
- Глобальная комбинация Ctrl+Shift+Space скрывает/показывает активное
  представление. Скрытие не останавливает мониторинг. При конфликте
  регистрации комбинации приложение сообщает об этом и остаётся доступным
  через обычное управление окнами.
- Оверлей получает клики внутри своих границ; за пределами окна управление
  остаётся у игры. Прозрачность для кликов не входит в эту первую версию.
- Закрытие завершает приложение, сигнализирует остановку анализа и
  освобождает глобальную горячую клавишу.

## Реализация

Использовать существующий Tkinter и отдельный модуль управления оверлеем.
Полный интерфейс сохраняется и переключается с компактной панелью без
повторного создания его виджетов. Окно имеет флаг topmost. Глобальная
горячая клавиша реализуется Windows RegisterHotKey; события обрабатываются
без вызовов Tkinter из фонового потока.

Расчёты, API и структура результатов остаются существующими. Найденный
дефект фильтрации недоступных для аукциона предметов описан отдельно в
API_DIAGNOSTICS.md и не считается исправленным этой работой.

Настройки оверлея сохраняются в `overlay_settings.json` рядом с программой;
файл исключается из Git. Повреждённые настройки заменяются значениями по
умолчанию. Окно при восстановлении должно оставаться доступным на экране.
Ключ читается из локального `exbo.json`, не включается в EXE и не коммитится.

## Проверка готовности

1. Проверки переключения режимов: результаты, вкладка и запущенный анализ
   сохраняются; повторный рабочий поток не появляется.
2. Проверки настроек: сохранение положения, повреждённый файл, недоступные
   координаты после смены экрана.
3. Проверка Windows: компактный старт, полный режим, сворачивание,
   перемещение, горячая клавиша и завершение.
4. Сборка отдельного EXE и проверка его запуска. Совместимость непосредственно
   с игрой подтверждается в запущенной игре; проверка на рабочем столе
   отдельно отмечается и не подменяет её.

Приложение не обращается к памяти или графическому процессу игры.
