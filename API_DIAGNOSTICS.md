## Проверка живого API

Для каждого из 55 предметов `ARSENAL` проверены история и текущие лоты
через `/RU/auction/{id}/history` и `/RU/auction/{id}/lots`.

## Причина

`auction_listing()` исключает предметы из `_no_auction()`, но статический
список `ARSENAL` передаётся в `sell_advice()` без этого фильтра.
`market_book()` запрашивает историю недоступного предмета. `get_json()`
повторяет запрос после любой ошибки, включая постоянную 400, затем передаёт
в интерфейс только общее сообщение HTTP без пояснения из тела ответа.

В `CONSUMABLES` также найден предмет из списка запретов: `7lyd3`,
«Анаболик STARK». Его живой ответ в этой проверке не запрашивался.

## Проверка функций приложения

`market_book('gnk55', 2)` успешно обработал 400 продаж соленоида.
`sell_advice()` получил медианную цену за единицу 2250 и предложил ту же
цену продажи. Значения рынка относятся только к моменту проверки.

Военный радиопередатчик (`9d10q`) имеет 3 записи истории и не имеет текущих
лотов. Сообщение «мало сделок» соответствует порогу `usual_sale()`:
необходимо минимум 6 наблюдений.

## Следующее исправление

1. Применить проверку доступности аукциона к тематическим разделам;
   показывать понятный статус для недоступных предметов без запросов к API.
2. Не повторять постоянные ошибки 400; отличать их от временных сетевых
   ошибок и ограничений частоты запросов.
3. Добавить регрессионные проверки фильтрации и обработки ошибок.

Исправления поведения пока не внесены. Все категории и полный прогон
приложения не проверялись. Проверка не доказывает прибыльность рекомендаций.
Секреты не включены в отчёт; ключ остаётся в игнорируемом `dist/exbo.json`.
